# ADR-0033: CORS の許可オリジンを環境変数で設定し、起動時に検証する

- ステータス: Accepted
- 日付: 2026-10-14
- 関連: #218, ADR-0032

## コンテキストと課題

CORS の許可オリジンは `internal/middleware/cors.go` に `http://localhost:3000` だけが直書きされていた。
本番（ADR-0032）では本番のフロントのオリジンを許可する必要があり、コードを変えずに環境ごとに値を切り替えたい。

前提・制約は次のとおり。

- `AllowCredentials: true` を設定している。CORS の仕様上、認証情報（Cookie など）付きのリクエストに
  `Access-Control-Allow-Origin: *` は使えない。
- 使用ライブラリ gin-contrib/cors（v1.7.7）は、許可オリジンの値を次のように解釈する（ソースで確認）。
  - `*` が 1 つでもあると全オリジン許可になり、`Access-Control-Allow-Origin: *` を返す。
  - `/.../` で囲んだ値は正規表現として扱う。
  - それ以外は完全一致で照合する。照合に使う設定値は小文字化・前後空白除去される。
  - 設定が不正な場合（空など）は `cors.New` が panic する。スキームの検証は小文字化の前に大文字小文字を区別して行うため、
    `HTTP://example.com` でも panic する。
- ブラウザが送る `Origin` は `scheme://host[:port]` の形で、パスや末尾スラッシュを含まない。
  `https://example.com/` のように設定すると一致せず、本番のフロントから API を呼べないまま気付きにくい。
- 本番のフロントのオリジンはフロント側（NatuIve_Web_Frontend#328）、プレビュー環境の扱いは #330 で決まる。

## 決定

**許可オリジンを環境変数 `CORS_ALLOW_ORIGINS`（カンマ区切り）で設定し、`scheme://host[:port]` の完全一致だけを受け付ける。
不正な値があればサーバーを起動しない。**

1. 前後の空白は除き、空の要素は無視する。各値は小文字化してからライブラリに渡す（スキームとホストは大文字小文字を区別しない）。
2. 未設定（または空文字）なら `http://localhost:3000` を使う。
3. 各値を起動時に検証し、次のいずれかに当たればエラーにして起動を止める。
   - `*` を含む（全許可・ワイルドカード）
   - スキームが `http`／`https` 以外、またはホストがない（`/.../` の正規表現形式もここで弾かれる）
   - `scheme://host[:port]` 以外の部分（パス・末尾スラッシュ・クエリ・フラグメント・ユーザー情報）を含む
   - ポートが空（`https://example.com:`）
   - 有効な値が 1 つも残らない（`CORS_ALLOW_ORIGINS=,` など）
4. プレビュー環境向けのワイルドカード・正規表現は、本 ADR では対応しない。#330 で必要になったら別の ADR で決める。

## 理由

- **起動時に止める**: CORS の設定ミスはリクエスト時に CORS エラーとして見えるだけで、原因が追いにくい。
  起動を止めれば、デプロイ直後にログで気付ける。ライブラリの panic に任せず、先に検証してエラーとして返す。
- **`*` を拒否する**: `AllowCredentials: true` と組み合わせると、認証情報付きのリクエストはブラウザに拒否される。
  また全オリジン許可になり、許可するオリジンを絞るという設定の目的に反する。
- **正規表現・ワイルドカードを受け付けない**: 環境変数の値がそのまま正規表現として解釈されると、
  `.` の書き忘れなどで意図しないオリジンを許可しうる。完全一致だけなら、許可範囲が設定値から明らかになる。
- **既定値を `http://localhost:3000` にする**: ローカル開発では設定不要になる。本番で設定を忘れても許可されるのは
  localhost だけで、許可範囲が広がる方向には倒れない（フロントから呼べないことで気付ける）。

## 影響（結果）

### 良い影響

- 本番のフロントのオリジンを、コードを変えずに Cloud Run の環境変数で設定できる。
- 設定ミス（末尾スラッシュ・`*` など）で起動しなくなるため、誤設定のまま運用されない。

### トレードオフ・制約

- 本番で `CORS_ALLOW_ORIGINS` を設定し忘れると、起動はするがフロントから API を呼べない（既定値が localhost のため）。
- プレビュー環境のように URL が変わるオリジンは、そのままでは許可できない。都度、完全一致の値を追加する必要がある。
- 既定ポート付きの値（`https://example.com:443` など）は検証では弾かないが、ブラウザの `Origin` には既定ポートが付かないため一致しない。

## 検討した代替案

- **末尾スラッシュを除いて受け付ける**: 寛容だが、設定値と実際の照合値が食い違う暗黙の補正になる。不採用。
- **不正な値を警告ログで無視して起動する**: 起動は止まらないが、警告に気付かなければ CORS エラーの原因が追えない。不採用。
- **ライブラリのワイルドカード（`AllowWildcard`）・正規表現をそのまま使えるようにする**: プレビュー環境には便利だが、
  許可範囲を誤りやすい。プレビューの扱いが未決（#330）のため、必要になってから決める。不採用。
- **`GIN_MODE=release` のときは既定値を持たず、未設定なら起動を止める**: 設定忘れには早く気付けるが、
  起動の可否が別の環境変数に依存して分かりにくい。不採用。
