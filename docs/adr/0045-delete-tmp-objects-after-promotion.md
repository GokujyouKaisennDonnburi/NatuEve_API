# ADR-0045: メディア昇格後に一時領域の元オブジェクトを削除する

- ステータス: Accepted
- 日付: 2026-11-11
- 関連: #278, #41, #279, ADR-0039

## コンテキストと課題

R2 の公開ドメイン（`R2_PUBLIC_BASE_URL`）はバケット全体を配信するため、一時領域（`natueve/tmp/{profileID}/{uuid}{ext}`）のファイルも公開ドメインの URL から取得できる。画像は昇格時に EXIF/GPS を除去して最終キーへ保存するが、元の tmp オブジェクトを削除していなかったため、ライフサイクルルールで消えるまで元画像を URL から取得できた。

## 決定

イベント・レポート作成で昇格と DB 保存が完了した後に、API が一時領域の元オブジェクト（画像・PDF）を best-effort で削除する。

## 理由

昇格・DB 保存の成功後に削除することで、途中失敗時の再試行を妨げずに投稿完了時点での元ファイル取得を防げる。コードとテストで完結し、不要な元データを R2 に残さない。

## 影響（結果）

### 良い影響

- 投稿完了後は、元の画像・PDF を一時領域の URL から取得できない。
- 不要な元データがライフサイクルルールの期限まで R2 に残らない。

### トレードオフ・制約

- 投稿完了前は、URL を知る本人は元ファイルを取得できる。
- 削除に失敗した場合は警告ログを出し、残りはライフサイクルルールで回収される。

## 検討した代替案

- **ライフサイクルルール（自動削除）のみに頼る**: 投稿直後に元画像を取得できるため不採用。
- **Cloudflare WAF 等で `/natueve/tmp/*` を遮断する**: ダッシュボード設定が必要でバケット内に元データが残るため、まずは API での削除を採用。
