# ADR-0054: 一覧系 API と sitemap で取りやめ済みのイベントを返さない

- ステータス: Accepted
- 日付: 2026-11-26
- 関連: #311, #259, NatuEve_Web_Frontend#375, NatuEve_Web_Frontend#471, ADR-0012, ADR-0024, ADR-0027, ADR-0042, ADR-0043
- 変更: ADR-0012 の決定事項 7（一覧でも取りやめ済みを非表示にしない）の一覧に関する部分、ADR-0024 のトレードオフにある「中止されたイベントも時間で振り分けられる」、ADR-0027 の決定事項 7（キャンセル済みを一覧に含める）とトレードオフの「キャンセル済みイベントが各 status に混ざる」、ADR-0043 のコンテキストにある「取りやめ済みも sitemap に含める」を置き換える（Supersedes, 部分的）

## コンテキストと課題

ADR-0012 の決定 7 により、一覧系 API は取りやめ済みのイベントも返し、件数にも数えていた。フロントは受け取ったページから取りやめ済みを除いて表示している。

検証環境で ZAP のスキャンが作ったイベント 1,113 件を取りやめたところ、イベント一覧が「1110 件・74 ページ」と出るのに、1 ページ目に 1 件しか出なくなった（#311）。API は取りやめ済みを含めて 15 件ずつ返し、フロントはそこから 14 件を除いた。件数からも、そのページで除いた 14 件だけを引いていた。マイページとプロフィールの一覧も、同じやり方で除いている。

sitemap は、取りやめ済みも含めることにしていた（#259、ADR-0043）。ページを残し、構造化データの `eventStatus` で中止を検索エンジンに伝えるためである。

制約と前提は次のとおり。

1. **ページ分けと件数は API が決める**。フロントがページを受け取ってから除くと、件数・ページ数と中身が合わない。
2. **構造化データはまだない**（NatuEve_Web_Frontend#375 が Open）。sitemap に残しても、中止は検索エンジンに伝わらない。
3. **詳細ページは取りやめを表示していない**。フロントの `EventDetail.tsx` は `cancelledAt` を見ていない。
4. **イベントを削除する機能がない**。テストやスパムのイベントも、取りやめで片付けるしかない。
5. **詳細 API への直リンクがある**。取りやめの通知メールや共有リンクから、詳細ページが開かれる。

## 決定

**一覧系の API と sitemap 用の API は、取りやめ済みのイベント（`cancelled_at IS NOT NULL`）を返さず、件数にも数えない。詳細 API は、これまでどおり取りやめ済みも返す。**

1. `GET /api/v1/events`: 一覧・検索とも、取りやめ済みを返さず、`totalCount` にも数えない。
2. `GET /api/v1/me/events`・`GET /api/v1/profiles/{id}/events`: すべての種別の一覧と `counts`・`totalCount` から除く。主催者自身の `hosted` からも除く。
3. `GET /api/v1/sitemap/events`: 取りやめ済みを返さない。
4. `GET /api/v1/events/{id}`: 変えない。取りやめ済みも `cancelledAt` を付けて返す。
5. 参加申込・参加者一覧など、イベント 1 件を対象とする API の扱いは変えない。
6. 見直し: NatuEve_Web_Frontend#375 で構造化データが入ったら、取りやめ済みを sitemap に戻すかを見直す。

## 理由

- **除外は件数を数える側でしか正しくできない**: API で除けば、件数・ページ数・ページの中身が一致する。
- **sitemap に残す前提が成り立っていない**: 中止を伝える構造化データがなく、詳細ページにも取りやめが表示されない。検索から来た人は中止を知らずに申し込もうとし、`409` で初めて分かる。
- **取りやめが削除の代わりに使われる**: テストやスパムのイベントを検索エンジンへ伝え続けるのは、片付けた目的と逆になる。
- **詳細 API は直リンクの受け皿である**: 返さないと、メールや共有リンクから来た人が `404` になり、取りやめたことが分からない。

## 影響（結果）

### 良い影響

- 取りやめ済みが多くても、一覧の件数・ページ数と中身が一致する。
- 取りやめたテストやスパムのイベントが、一覧と sitemap に出なくなる。
- フロントで取りやめ済みを除く処理は不要になる。残しても、除く件数が 0 になるだけで害はない。

### トレードオフ・制約

- **主催者は自分が取りやめたイベントを一覧から探せない**: マイページの `hosted` から消える。詳細ページへは URL か通知メールから行ける。
- **参加者の `applied`・`attended` からも消える**: 取りやめは通知メールで伝わる前提である。
- **すでに検索結果に載ったページは消えない**: sitemap から外すだけでは、インデックスから外れない。外すには、フロントで `noindex` などが別に要る。
- **検索エンジンが中止を知るきっかけは、通常の再クロールだけになる**。
- **`cancelled_at` での絞り込みが、すべての一覧クエリに入る**: 取りやめ済みの割合が小さいうちは、インデックスを足していない。

## 検討した代替案

- **フロントで取りやめ済みを除く（現状）**: API を変えずに済む / 件数・ページ数と中身が合わないため不採用。
- **一覧に取りやめ済みを除くパラメータを足す**: 既存の呼び出しを変えない / フロントはすべての一覧で取りやめ済みを除いており、含めて受け取りたい呼び出し側がないため、既定を除外にした。必要になったら、含めるパラメータを足す。
- **sitemap には取りやめ済みを残す（ADR-0043 のまま）**: ページを残して中止を伝えられる / 構造化データも詳細ページの表示もない今は中止が伝わらず、片付けたイベントも検索エンジンに伝わり続けるため不採用。
- **詳細 API でも取りやめ済みを返さない**: 取りやめ済みが外から見えなくなる / 直リンクから来た人が `404` になり、取りやめたことが分からないため不採用。
