# ADR-0038: 利用者 IP の検証は本番の API で行い、ヘッダーを返す検証用アプリは使わない

- ステータス: Accepted
- 日付: 2026-10-23
- 関連: #241, #215, #242, #243, #244, ADR-0034

## コンテキストと課題

ADR-0034 で、利用者 IP は中継用 Worker が `CF-Connecting-IP` の値を利用者 IP 用のヘッダーに上書きして渡し、
API が Gin の `TrustedPlatform` で読む方式に決めた。参加申込の IP レート制限（`internal/middleware/ratelimit.go`）は
この値ごとに数える。

#215 の受け入れ基準には、デプロイ後に「Worker 経由と run.app の URL への直接アクセスのそれぞれで、コンテナに届く
接続元 IP と IP 系ヘッダーの中身を確認する」があった。API のリクエストログ（`internal/middleware/logger.go`）に
出るのは `c.ClientIP()` の結果（`ip`）だけで、接続元の IP やヘッダーの中身は出ない。
この確認のための手段を、デプロイ前に用意するかを決める必要があった（#241）。

## 決定

**利用者 IP の検証は本番の API に対して行い、リクエストログの `ip` と応答のステータスで確かめる。
コンテナに届く生のヘッダーを確かめるための検証用アプリは用意しない。**

1. #215 の確認項目（利用者 IP が取れる・偽装できない・run.app の URL への直接アクセスが拒否される・IPv6 が `/64` 単位で
   数えられる・参加申込のレート制限が利用者ごとに効く）は、#244 で本番の API に対して確かめる。
2. コンテナに届く生のヘッダーの中身は、#244 で利用者 IP が正しく取れなかった場合に調べる。調べ方はそのときに決める。
3. #215 の受け入れ基準から「コンテナに届く接続元 IP と IP 系ヘッダーの中身を確認する」を外し、#243 は対応しない。

## 理由

- #215 で確かめたいのは、利用者 IP が正しく取れることと偽装できないことで、どちらもログの `ip` と応答のステータスで判定できる。
  - 偽装は、`CF-Connecting-IP` などを偽の値にして独自ドメインへ送り、ログの `ip` が送信元の IP のままかで判定する。
    Cloudflare が利用者の付けた `CF-Connecting-IP` を上書きしなければ、Worker がその値を渡すため、偽の値が `ip` に出る。
  - run.app の URL への直接アクセスは、403 が返るかで判定する。
- 生のヘッダーの中身は判定の材料ではなく、うまく動かなかったときの原因調査の手がかりである。問題は利用者への公開前の確認で
  見つかるため、必要になってから用意しても間に合う。
- 検証用アプリを使うと、Worker の転送先を一時的に切り替えて戻す手間がかかる。戻し忘れると、独自ドメインから API に届かなくなる。

## 影響（結果）

### 良い影響

- 検証のためのコード・Dockerfile・手順を抱えない。
- 本番と同じ構成（Worker → API）のまま確かめられ、Worker の転送先を切り替えない。

### トレードオフ・制約

- Cloudflare と Cloud Run がコンテナに渡すヘッダーの中身（`X-Forwarded-For` に何が入るか等）は記録に残らない。
  中継の構成を変えたとき（ADR-0034 の決定事項 7）も、ログの `ip` と応答のステータスで確かめる。
- 利用者 IP が正しく取れなかった場合は、原因を調べる手段をその時点で用意する。

## 検討した代替案

- **ヘッダーを返すだけの検証用アプリを、API とは別の Cloud Run サービスとしてデプロイする**:
  Worker の転送先を一時的にそこへ向け、届いた接続元と IP 系ヘッダーの値を JSON で返させる。秘密ヘッダーは有無だけ、
  IP 系以外のヘッダーは名前だけを返し、Host は返さない。PR #245 で一度実装したが、上記の理由で取り下げた。
  原因調査が必要になった場合の候補とする。
- **API に一時的な記録を入れる（環境変数で有効にするログやエンドポイント）**: 検証のためのコードが本番のイメージに入る。
  run.app の URL への直接アクセスは中継元の確認で拒否されるため、そのヘッダーを記録すると、ADR-0034 の
  「拒否したリクエストのログに、偽装されたヘッダーの IP を記録しない」と両立しない。不採用。
- **Cloud Run のリクエストログで確かめる**: リクエストログの `httpRequest` に残るのは送信元 IP・User-Agent などの決まった項目で、
  コンテナに届くヘッダーの中身は残らない。不採用。
