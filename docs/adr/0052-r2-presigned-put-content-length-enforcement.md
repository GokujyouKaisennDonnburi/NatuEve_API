# ADR-0052: R2 の署名付き PUT で Content-Length を強制する

- ステータス: Accepted
- 日付: 2026-11-16
- 関連: R2 アップロード容量制限対応

## コンテキストと課題

NatuEve では、クライアントが Cloudflare R2 の tmp 領域へ直接ファイルをアップロードするため、署名付き PUT URL を発行している。

画像は 10MiB、PDF は 20MiB を上限とする必要がある。しかし、presign 時にクライアントが申告したサイズを検証するだけでは、実際に PUT されるファイルのサイズを強制できない。

R2 へのアップロード時点で、申告したサイズと実際のファイルサイズが一致することを保証する必要がある。

## 決定

署名付き PUT URL の署名対象に Content-Type と Content-Length を含め、presign 時に指定されたサイズと実際の PUT のサイズが一致する場合のみアップロードを許可する。

また、presign 時には kind に対応するサイズ上限を検証し、オブジェクト昇格時にも Head によるサイズと Content-Type の検査を維持する。

## 理由

署名付き POST のポリシーに content-length-range を指定する方式を検討したが、Cloudflare R2 では 501 NotImplemented が返されるため採用できない。

一方、署名付き PUT の署名対象に Content-Length を含めることで、クライアントが presign 時に申告したサイズと実際の PUT のサイズを一致させることができる。

サイズが一致しない場合、R2 は 403 SignatureDoesNotMatch を返し、アップロードを拒否する。

ただし、この 403 応答だけでは、容量超過と申告サイズとの不一致を区別できない。そのため、presign 時の上限検証と、昇格時のサーバー側検査を併用する。

## 影響（結果）

### 良い影響

- presign 時に申告したサイズと実際のアップロードサイズが一致しない PUT を拒否できる。
- 画像 10MiB、PDF 20MiB の上限を、presign 時の検証と署名検証の組み合わせで強制できる。
- 昇格時にもサイズと Content-Type を検査することで、多層防御を維持できる。

### トレードオフ・制約

- クライアントは presign 時に実際のファイルサイズをバイト単位で指定する必要がある。
- PUT 時には presign 時と同じ Content-Length と Content-Type を指定する必要がある。
- サイズまたは Content-Type が一致しない場合、R2 は 403 を返す。容量超過とサイズ不一致を R2 の応答だけで区別することはできない。
- Content-Length を署名対象に含めるため、アップロード時に実際のサイズが確定している必要がある。

## 検討した代替案

- **署名付き POST の content-length-range**: サイズ範囲をポリシーで制限できるが、Cloudflare R2 が 501 NotImplemented を返すため不採用。
- **presign 時の申告サイズだけを検証する**: 実際の PUT サイズを強制できないため不採用。
- **昇格時の Head による検査だけで制限する**: tmp 領域へのアップロード自体は許可されてしまうため、単独では不十分。追加の防御としては維持する。
